# 系统架构设计

## 一、业务框架

### 核心闭环

```
策略定义(自然语言) → 结构化存储 → 回测执行(LLM逐日决策) → 交易撮合 → 绩效评估 → 结果报告 → 策略优化 → 再回测（闭环）
```

| 阶段 | 说明 |
|---|---|
| 策略定义 | 用户用自然语言写“牛市期间买入热门板块的龙头股”，系统抽取成结构化策略（含择时/仓位/风控配置） |
| 回测执行 | 每个交易日 = 一个决策回合：LLM 读策略 → 调工具看市场 → 决策买卖 |
| 交易撮合 | 按 A 股真实规则成交（T+1、涨跌停、ST 5% 限制、佣金/印花税/滑点、100 股整数倍、流动性约束） |
| 绩效评估 | 收益 / 回撤 / 夏普 / 胜率，与沪深 300 基准对比 |
| 复盘追溯 | 每步「观察 → 工具调用 → 决策 → 成交」全留痕，可下钻 |
| 策略优化 | 基于报告诊断短板，LLM 产出「诊断 + 逐条改动 + 优化后策略 + 配置」，保存为新策略再回测 |

### 业务域模块

1. **策略管理** —— 自然语言策略的创建、编辑、版本化、参数化
2. **数据域** —— 本地数据湖（行情/财务/资金流/板块/指数），本地优先、在线兜底
3. **工具域** —— 统一工具注册表：内置 + 数据查询 + 大模型自造工具
4. **执行域** —— LLM 驱动策略执行 Agent（逐日决策循环 + 记忆）
5. **回测域** —— 撮合、账户、风控、A 股规则、绩效归因
6. **看板域** —— Web 可视化 + 任务中心 + 数据管理
7. **知识域** —— 股票交易知识库（九大一级领域 + 二级子类 + 跨维度标签，知识图谱/思维导图，录入/链接吸收，策略生成与优化时 RAG 注入）

### 「自造工具」闭环

```
策略需求 → LLM 识别工具缺口 → 生成声明式 SQL 工具 → 校验(仅SELECT/参数化/试运行) → 注册工具库 → 复用
```

## 二、技术选型

| 层 | 选型 |
|---|---|
| 后端 | Python 3.11+ / FastAPI / Pydantic |
| 本地数据湖 | Parquet 存储 + DuckDB 查询引擎 |
| 在线补数 | 腾讯/新浪直连 HTTP（`app/data/sources.py`）为主，akshare（`app/data/akshare_source.py`）可选 |
| LLM 层 | 统一网关 + 多 provider 按需路由（OpenAI 兼容封装）+ 失败 fallback |
| 工具协议 | OpenAI Function Calling（JSON Schema） |
| 回测执行 | 时间循环 + asyncio 后台任务 |
| 前端 | React + TypeScript + Vite + ECharts |
| 运行形态 | 单机（Python venv + npm），跨平台一键部署脚本 |

### 数据源

- **开源包内置（离线可用）**：HuggingFace [`ANTICH/traderharness-ashare-5y`](https://huggingface.co/datasets/ANTICH/traderharness-ashare-5y) 的 Parquet 数据（daily / valuation / fundamentals / dividends / index_300）。
- **动态更新**：默认走「腾讯快照 + 腾讯后复权 K 线 + 新浪列表/行业」直连 HTTP 源（`app/data/sources.py`）补齐与增量；`app/data/scheduler.py` 后台线程每交易日收盘后自动增量更新；`app/data/updater.py` 编排历史回填与元数据回填。
- **可选数据源（akshare）**：设置环境变量 `DATA_SOURCE=akshare`（或 `AKSHARE_ENABLED=1`）启用，与直连源返回**同构 dict**、可无缝替换；查询 `GET /api/data/source` 查看当前数据源。

### 数据 schema（DuckDB 表）

- `stocks`（代码/名称/行业/上市日/退市日/状态）
- `daily`（日期/OHLCV/复权因子/涨跌幅/换手/流通市值/PE/PB）
- `indices`（沪深 300 等基准）
- `finances`（季度财务：营收/净利/ROE/毛利率/同比等）
- `moneyflow`（主力/大单/超大单净流入）
- `sectors`（板块成分/板块行情/板块资金流）
